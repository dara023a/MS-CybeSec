D+E // Deep Dive & Technical Notes

ANALYSIS NODE
D

Deep Dive Material

Linux memiliki struktur direktori yang konsisten: /home untuk data pengguna, /etc untuk konfigurasi, /var/log untuk log, /bin dan /usr/bin untuk program, /tmp untuk file sementara, serta /root untuk akun root. Hak akses sangat penting: user biasa dibatasi, sudo memberi izin administratif sementara, sedangkan root memiliki kendali penuh. Di cyber security, kesalahan memahami permission dapat membuat analisis salah atau merusak lab. Apache2 digunakan sebagai contoh server lokal agar recruit memahami hubungan service, konfigurasi, port, dan log.


Hubungan offensive dan defensive: recruit belajar memahami root cause, dampak, bukti teknis, serta cara mengubah temuan menjadi rekomendasi perbaikan.

O // Textbook Chapter

DEEP MATERIAL NODE
FULL CHAPTER MODE

Linux sebagai Sistem Kerja Cyber Security

Bab ini menjelaskan Linux dari fondasi praktis: struktur sistem file, user privilege, command line, service, package manager, permission, dan log. Tujuannya agar recruit tidak hanya menghafal perintah, tetapi memahami apa yang terjadi saat sistem dijalankan.

Mengapa Linux penting dalam cyber security

Linux banyak dipakai di server, cloud, container, perangkat jaringan, sistem keamanan, dan distribusi khusus seperti Kali Linux. Seorang cyber security engineer perlu memahami Linux karena banyak target legal, lab, dan infrastruktur produksi berjalan di atas Linux. Memahami Linux berarti memahami bagaimana file disimpan, proses berjalan, service dikelola, permission diterapkan, dan log dicatat.

Kali Linux sering diasosiasikan dengan penetration testing, tetapi Kali bukan “alat ajaib”. Kali hanyalah distribusi Linux yang sudah menyediakan banyak tools keamanan. Tools tersebut tetap membutuhkan pemahaman sistem operasi. Tanpa memahami file permission, user privilege, network interface, dan log, recruit mudah salah membaca output atau menjalankan command berisiko.

Filesystem dan privilege

Struktur folder Linux memiliki fungsi yang jelas. /home berisi data user, /etc berisi konfigurasi, /var/log berisi log, /usr dan /bin berisi program, sedangkan /tmp dipakai untuk file sementara. Dalam investigasi atau hardening, lokasi ini penting. Misalnya, konfigurasi Apache berada di area /etc, sedangkan log akses web server biasanya berada di /var/log/apache2 atau lokasi serupa tergantung distro.

Privilege Linux dibagi antara user biasa dan root. Root memiliki kuasa penuh, sehingga kesalahan kecil dapat merusak sistem. Perintah sudo memberi hak administratif sementara. Dalam praktik keamanan, prinsip yang benar adalah least privilege: gunakan hak minimum yang cukup untuk tugas tertentu. Jika sebuah service web tidak perlu berjalan sebagai root, maka jangan jalankan sebagai root.

Permission, proses, dan service

Permission Linux mengatur siapa yang boleh membaca, menulis, dan mengeksekusi file. Kombinasi user, group, dan others menentukan batas akses. Kesalahan permission bisa menjadi celah serius. File konfigurasi yang menyimpan secret tidak boleh world-readable. Script yang dapat ditulis semua orang tetapi dijalankan oleh service privileged dapat menjadi risiko integritas sistem.

Linux menjalankan banyak proses. Command seperti ps, top, dan systemctl membantu melihat proses dan service. Dari perspektif defender, proses tidak dikenal, service yang tiba-tiba aktif, atau penggunaan CPU tidak biasa dapat menjadi sinyal investigasi. Namun analisis harus hati-hati: tidak semua hal aneh berarti serangan, dan tidak semua serangan terlihat jelas.

Log sebagai sumber kebenaran operasional

Log adalah catatan aktivitas sistem. Apache access log mencatat request, status code, user-agent, dan IP sumber. Auth log mencatat login dan penggunaan privilege. Defender menggunakan log untuk menjawab pertanyaan: apa yang terjadi, kapan terjadi, dari mana asalnya, akun apa yang terlibat, dan apakah dampaknya menyebar. Tanpa log yang rapi, incident response menjadi spekulasi.

Skenario lapangan

Seorang admin melihat server web lambat. Ia memeriksa service Apache, membaca access log, dan menemukan banyak request error ke endpoint yang tidak ada. Ia tidak langsung menyimpulkan “diserang”, tetapi mengelompokkan pola request, mengecek apakah ada perubahan file, melihat auth log, lalu menerapkan rate limiting atau aturan monitoring jika pola tersebut terbukti berisiko. Ini contoh cara Linux digunakan sebagai dasar analisis keamanan.
