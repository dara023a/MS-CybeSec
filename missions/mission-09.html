Deep Dive Material

Reflected XSS muncul langsung dari request, stored XSS tersimpan di aplikasi, DOM XSS terjadi di logika JavaScript sisi klien, sedangkan blind XSS terlihat ketika payload diproses di panel lain secara konseptual. O // Textbook Chapter

DEEP MATERIAL NODE
FULL CHAPTER MODE

HTML Injection, XSS, dan Clickjacking

Bab ini menjelaskan risiko ketika aplikasi menampilkan data user tanpa pengendalian output. Fokusnya adalah browser sebagai runtime, konteks output, Content Security Policy, dan kontrol framing.

Browser sebagai mesin eksekusi

Aplikasi web tidak hanya mengirim teks; ia mengirim HTML, CSS, JavaScript, dan data yang akan diproses browser. HTML Injection terjadi ketika input user ditampilkan sebagai markup HTML tanpa encoding yang tepat. XSS atau Cross-Site Scripting terjadi ketika attacker di lab dapat membuat browser menjalankan script dalam konteks aplikasi. Risiko XSS besar karena script berjalan dengan kepercayaan domain aplikasi, sehingga dapat membaca bagian DOM, memicu aksi user, atau menyalahgunakan session jika kontrol cookie lemah.

XSS memiliki beberapa bentuk. Reflected XSS muncul ketika input dipantulkan langsung dalam response. Stored XSS tersimpan di server dan berdampak pada user lain yang membuka halaman tersebut. DOM-based XSS terjadi ketika JavaScript client-side memproses data tidak tepercaya dan menuliskannya ke DOM secara tidak aman. Blind XSS muncul ketika input dieksekusi di panel internal yang tidak langsung terlihat tester.

Konteks output menentukan mitigasi

Mitigasi XSS bukan hanya “filter karakter”. Yang benar adalah output encoding sesuai konteks. Data yang masuk ke HTML body membutuhkan encoding HTML. Data yang masuk ke atribut membutuhkan encoding atribut. Data dalam JavaScript, URL, atau CSS memiliki aturan berbeda. Karena itu, framework modern membantu dengan auto-escaping, tetapi developer tetap harus berhati-hati ketika memakai fitur seperti raw HTML rendering.

Content Security Policy dapat mengurangi dampak XSS dengan membatasi sumber script, style, frame, dan koneksi. Namun CSP adalah lapisan tambahan. Akar perbaikan tetap validasi input, sanitasi untuk rich text, dan output encoding.

Clickjacking

Clickjacking terjadi ketika halaman aplikasi ditanam dalam frame transparan atau menipu user agar mengklik sesuatu yang berbeda dari yang terlihat. Kontrolnya adalah X-Frame-Options atau directive CSP frame-ancestors. Fitur sensitif seperti transfer, pengubahan email, atau aksi administratif sebaiknya dilindungi dari framing tidak sah.

Deteksi dan skenario lapangan

Defender memantau laporan error JavaScript, input berisi markup tidak lazim, CSP violation report, dan perubahan konten yang tidak biasa. Misalnya, aplikasi forum kampus membolehkan komentar rich text. Developer harus menggunakan sanitizer yang matang, membatasi tag/atribut, dan memastikan output di-encode. Laporan yang baik menjelaskan konteks output, dampak, dan remediation, bukan sekadar menaruh payload.
