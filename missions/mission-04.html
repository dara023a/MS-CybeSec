D+E // Deep Dive & Technical Notes

ANALYSIS NODE
D

Deep Dive Material

Request memiliki method, path, header, cookie, dan kadang body. Response memiliki status code, header, dan body. Session menjaga keadaan login karena HTTP bersifat stateless. Cookie menyimpan identitas sesi di browser, sedangkan JWT membawa klaim yang harus divalidasi dengan benar. Hash berbeda dari encryption: hash satu arah, encryption bisa dikembalikan dengan kunci. Password storage aman memakai hashing adaptif seperti bcrypt atau Argon2 dengan salt, bukan MD5.


Hubungan offensive dan defensive: recruit belajar memahami root cause, dampak, bukti teknis, serta cara mengubah temuan menjadi rekomendasi perbaikan.

O // Textbook Chapter

DEEP MATERIAL NODE
FULL CHAPTER MODE

Cara Kerja Web Application, HTTP, Session, dan Kriptografi Dasar

Bab ini menjelaskan bagaimana browser, server, backend, database, cookie, session, TLS, hashing, dan token bekerja. Web security tidak bisa dipahami tanpa memahami alur request-response dan batas antara identitas, data, dan transport.

Web sebagai percakapan request dan response

Aplikasi web bekerja melalui pola client-server. Browser mengirim request, server mengirim response. Request berisi method, path, header, cookie, body, dan parameter. Response berisi status code, header, dan body. Kesalahan keamanan sering terjadi karena developer terlalu percaya pada data yang datang dari client. Padahal semua data dari browser dapat dimodifikasi oleh user, proxy, ekstensi, atau script.

Method HTTP seperti GET, POST, PUT, dan DELETE menggambarkan niat operasi, tetapi keamanan tidak boleh bergantung pada method saja. Endpoint sensitif harus memverifikasi autentikasi, otorisasi, CSRF protection jika relevan, validasi input, dan logging. Status code juga penting. Status 200, 401, 403, 404, dan 500 memberi petunjuk alur aplikasi. Namun error terlalu detail dapat membocorkan informasi internal.

Cookie, session, dan token

Session adalah cara server mengingat bahwa user sudah login. Biasanya browser menyimpan session identifier dalam cookie. Jika cookie dicuri, ditebak, atau tidak dilindungi, pihak lain bisa menyamar sebagai user. Karena itu cookie sensitif sebaiknya menggunakan atribut HttpOnly, Secure, dan SameSite. Session juga perlu expired, rotasi setelah login, dan invalidasi saat logout.

JWT adalah format token yang berisi klaim dan tanda tangan. JWT bukan enkripsi otomatis. Banyak pemula salah paham karena isi JWT tampak “acak”, padahal bagian payload dapat dibaca setelah base64url decoding. Risiko muncul jika secret lemah, algoritma tidak divalidasi, token terlalu panjang masa berlakunya, atau aplikasi mempercayai klaim tanpa verifikasi.

Hash, encryption, salting, dan password storage

Hashing mengubah data menjadi fingerprint satu arah. Password tidak seharusnya disimpan dalam bentuk plaintext. Namun hash cepat seperti MD5 dan SHA-1 tidak cocok untuk password modern karena dapat ditebak dengan cepat menggunakan wordlist. Password storage yang baik memakai algoritma lambat dan dirancang untuk password seperti bcrypt, scrypt, atau Argon2, ditambah salt unik.

Encryption berbeda dari hashing. Encryption dapat dibalik jika memiliki kunci. TLS menggunakan kriptografi untuk melindungi data saat bergerak antara client dan server. HTTPS tidak otomatis membuat aplikasi aman dari SQLi, XSS, atau IDOR, tetapi melindungi data dari penyadapan jaringan.

Peran proxy dalam pembelajaran aman

Burp Suite atau proxy serupa membantu melihat request-response pada lab legal. Tujuannya bukan menyerang target publik, tetapi memahami data apa yang dikirim aplikasi. Dari sisi defender, pemahaman ini membantu membuat validasi server-side, logging yang baik, dan kontrol akses yang tidak bergantung pada UI.
